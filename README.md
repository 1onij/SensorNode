# SensorNode：姿态与环境采集节点（STM32F103C8T6 · 标准库）

> STM32 定时采集 MPU6050 姿态和 AHT20 温湿度，在 OLED 上显示；通过串口按自定义二进制协议（或 VOFA+ JustFloat）上报，用 DMA 后台发送；电脑可以发命令开关上报、切换格式、清除零偏。陀螺仪零偏存在 W25Q64 Flash 里，掉电不丢。

## 功能

- [x] 软件 I2C（PB6/PB7）读 MPU6050、AHT20，驱动 SSD1306 OLED，三个器件共用一条总线
- [x] 加速度算 Roll / Pitch，陀螺仪积分，互补滤波（0.98 / 0.02），dt 用实测值
- [x] 开机零偏校准（静止 2 秒，200 次取平均），结果存进 W25Q64，下次上电直接读取
- [x] TIM2 1 ms 节拍 + 主循环非阻塞调度，主循环里不用 Delay 干等
- [x] OLED 分 8 次刷新（每 12 ms 刷 1 项），避免一次刷屏卡住 MPU 任务
- [x] 串口每 20 ms 上报一次：AA 55 二进制数据帧，或 VOFA+ JustFloat 看曲线
- [x] 串口上报用 DMA1 通道 4 后台发送，CPU 不用逐字节等 TXE
- [x] 串口接收中断 + 状态机解析命令帧（带长度和校验），每条命令都回应答帧

## 软件结构

```
Start/      启动文件、CMSIS
Library/    ST 标准外设库
System/     Delay
hardware/   I2C  MPU6050  AHT20  OLED  SPI  W25Q64  Serial  Frame  Timer  LED   ← 驱动层
User/       main.c  stm32f10x_it.c                                             ← 应用层
```

分层原则：只能上层调下层。驱动只管“把数读出来 / 发出去”，Frame 只管“字节怎么排”，main 只管“什么时候做什么”。例如串口改成 DMA 发送时，只改了 Serial.c 和 Frame.c，main 里的调度没动。

### 程序怎么跑

- **中断**：TIM2 每 1 ms 让 tick 加 1；USART1 接收中断里用状态机收命令帧，收完整一帧且校验正确才置标志。
- **主循环**：每圈取一次 `Now`，按 `if (Now - LastXxx >= 周期)` 轮流检查各任务：

| 任务 | 周期 | 说明 |
| --- | --- | --- |
| MPU6050 + 姿态解算 | 10 ms | dt 用两次实际间隔 |
| 串口上报 | 20 ms | 格式由命令 0x04 切换，DMA 发送 |
| OLED 刷新 | 每 12 ms 刷 1 项，8 项一轮 | 避免一次刷屏卡 100 多 ms |
| AHT20 | 每 1000 ms 触发，80 ms 后读结果 | 不用 Delay 等测量 |
| LED 心跳 | 500 ms | 看程序有没有卡死 |
| 处理串口命令 | 每圈 | 标志为 1 就处理 |

### 串口 DMA 发送流程

DMA1 通道 4（USART1_TX），内存 `TX_Buf[64]` → 外设 `USART1->DR`，字节宽度，内存自增，Normal 模式。每次发送：

```
TX_Busy 为 1 就等 TC4  →  清 TC4  →  关通道  →  数据拷进 TX_Buf  →  设 CNDTR = Len  →  开通道  →  TX_Busy = 1
```

- 调用者传进来的是局部数组，函数返回后就失效，所以要先拷进全局的 `TX_Buf`。
- 上电时 TC4 是 0，第一次直接等会卡死，所以用 `TX_Busy` 记“发过没有”。
- VOFA 帧先在函数里拼成完整的 36 字节，只调一次发送。

## 串口协议

波特率 115200，8N1。多字节整数**高字节在前**。

### 电脑 → 板子：命令帧

```
AA 55 | LEN | CMD | DATA ... | SUM
```

| 字段 | 字节数 | 说明 |
| --- | --- | --- |
| 帧头 | 2 | 固定 0xAA 0x55 |
| LEN | 1 | CMD + DATA 的字节数，1–8 |
| CMD | 1 | 命令字 |
| DATA | LEN − 1 | 参数 |
| SUM | 1 | LEN + CMD + DATA 逐字节相加，取低 8 位 |

| CMD | DATA | 含义 | 例子（HEX 发送） |
| --- | --- | --- | --- |
| 0x01 | 无 | 开始上报 | `AA 55 01 01 02` |
| 0x02 | 无 | 停止上报 | `AA 55 01 02 03` |
| 0x03 | 无 | 擦除 Flash 里的零偏，下次上电重新校准 | `AA 55 01 03 04` |
| 0x04 | 无 | 在 AA 55 数据帧和 VOFA+ 之间切换 | `AA 55 01 04 05` |

### 板子 → 电脑：应答帧

每收到一条命令都回一帧，格式和命令帧相同：CMD = 原命令 | 0x80，DATA 1 字节是结果（0 成功，2 不认识的命令）。

```
发送：AA 55 01 02 03      （停止上报）
应答：AA 55 02 82 00 84

发送：AA 55 01 09 0A      （不认识的命令 0x09）
应答：AA 55 02 89 02 8D
```

在 VOFA 模式下，应答字节会混进 JustFloat 数据流，曲线会闪一下；想看应答可以先发 `AA 55 01 02 03` 停止上报。

### 板子 → 电脑：AA 55 数据帧（上电默认）

共 24 字节：

```
AA 55 | 14 | ax ay az gx gy gz | temp | humi | roll | pitch | SUM
```

| 字节 | 内容 |
| --- | --- |
| 0–1 | 帧头 AA 55 |
| 2 | 数据长度 0x14（20） |
| 3–14 | 加速度 X/Y/Z、陀螺仪 X/Y/Z 原始值，int16，各 2 字节（±16g，±2000°/s） |
| 15–16 | 温度 × 10，int16（27.3 ℃ → 273） |
| 17–18 | 湿度 × 10，int16 |
| 19–20 | Roll × 10，int16（互补滤波后） |
| 21–22 | Pitch × 10，int16（互补滤波后） |
| 23 | 校验：第 2–22 字节相加取低 8 位 |

### 板子 → 电脑：VOFA+ JustFloat（命令 0x04 切换）

8 个 float（小端）+ 帧尾 `00 00 80 7F`，共 36 字节。

| 通道 | 内容 |
| --- | --- |
| I0 / I1 | 温度（℃）/ 湿度（%RH） |
| I2 / I3 | 加速度算的 Roll / Pitch |
| I4 / I5 | 陀螺仪积分的 Roll / Pitch |
| I6 / I7 | 互补滤波后的 Roll / Pitch |

### Flash 存储格式

地址 0x000000（第 0 扇区），共 10 字节：`A5 5A | OffX (float, 4 字节) | OffY (float, 4 字节)`。上电读到 A5 5A 就直接用存的零偏，否则重新校准并写入（先扇区擦除，再页编程）。

## 遇到的问题和解决

- **陀螺仪积分角度几乎不动**：OLED 一次刷完 8 项要约 1018 ms，MPU 任务一秒只跑一次，而积分按 0.01 秒算。→ 测出每个任务的耗时，把 OLED 拆成每圈只刷 1 项；dt 改用两次实际间隔，不写死 0.01。
- **互补滤波后 Roll 比加速度角固定差约 9°**：推导出偏差 = 49 × 零偏 × dt，是陀螺仪零偏造成的。→ 开机静止采 200 次求平均，积分前先减掉。
- **W25Q64 写进去读出来不对**：Flash 只能把 1 写成 0，写之前必须先擦除；页编程不能跨 256 字节的页；每次擦除 / 写之前要写使能，之后要等 BUSY 清零。
- **地址字节发错**：`(uint8_t)Address >> 16` 先强转再移位，结果恒为 0。→ 写成 `(uint8_t)(Address >> 16)`。
- **DMA 发出的每个字节后面多了 3 个 00**：发送缓冲区声明成了 `uint32_t`，0xAA 在内存里是 `AA 00 00 00`，DMA 按字节搬就全发出去了。→ 缓冲区用 `uint8_t`，只有把地址交给 DMA 时才写 `(uint32_t)TX_Buf`。
- **DMA 第一次发送卡死**：上电时 TC4 是 0，直接 while 等 TC4 永远等不到。→ 用 `TX_Busy` 区分“没发过”和“发过”，发过才等。
- **串口中断偶尔把 0 当成收到的字节**：状态机写在 `if (RXNE)` 外面，不是 RXNE 引起的中断也会推进状态机。→ 把 switch 移进 if 里面。
